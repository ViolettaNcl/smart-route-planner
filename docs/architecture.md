# Архитектура приложения

## Общий обзор

Приложение представляет собой одностраничный PHP‑сервис, разделённый на слой представления (`index.php`) и слой бизнес‑логики (`route_logic.php`). Взаимодействие с пользователем происходит через HTML‑форму, а вычисления маршрута выполняются на сервере.

База данных не используется, все данные живут только в рамках одного HTTP‑запроса.

## Структура файлов

```text
index.php          # Веб‑интерфейс и точка входа
route_logic.php    # Функции геокодирования, расстояния и выбора транспорта
route.css          # Стили оформления страницы
```

- `index.php` подключает `route_logic.php`, выполняет всю логику и рендерит HTML.
- `route_logic.php` содержит функции `getCoords`, `distanceKm`, `predictTransportNN` и основную последовательность вычислений.
- `route.css` отвечает только за внешний вид.

## Поток данных

1. Пользователь отправляет форму с текстовым полем `points`.
2. PHP разбивает строку по символу `;`, очищает пробелы и фильтрует пустые значения.
3. Для каждого города вызывается `getCoords($city)`, которая обращается к API Nominatim и возвращает широту/долготу.
4. Формируется массив координат только для тех городов, которые успешно геокодированы.
5. Функция `distanceKm` по формуле гаверсинусов считает расстояние между соседними точками маршрута.
6. Все отрезки суммируются и результат округляется до целых километров.
7. Функция `predictTransportNN` по расстоянию и количеству точек выбирает режим транспорта.
8. Генерируются ссылки `googleUrl` и `yandexUrl` для открытия маршрута в картах.
9. `index.php` выводит рассчитанные значения и ссылки на экран.

## Компоненты и их ответственность

| Компонент         | Ответственность                                              |
|-------------------|--------------------------------------------------------------|
| `index.php`       | Обработка формы, подключение логики, рендер HTML и подключение CSS. |
| `route_logic.php` | Геокодирование, расчёт расстояния, выбор транспорта.        |
| `route.css`       | Визуальное оформление интерфейса.                           |
| OpenStreetMap API | Внешний сервис для преобразования города в координаты.      |

## Взаимодействие с внешними системами

- **OpenStreetMap Nominatim**: HTTP‑запрос `search?format=json&q=<city>` с заголовком `User-Agent`. В ответ приходит JSON‑массив, берётся первая пара координат.
- **Google Maps**: URL `https://www.google.com/maps/dir/<точка1>/<точка2>/...`.
- **Яндекс.Карты**: URL `https://yandex.ru/maps/?rtext=<точка1>~<точка2>~...&rtt=auto`.

## Ограничения и допущения

- Маршрут строится строго в том порядке, в котором пользователь указал точки.
- Если какой‑то город не геокодировался, он молча пропускается.
- Между запросами к Nominatim стоит `usleep(200000)` (0,2 секунды), чтобы не спамить API.
- Модель выбора транспорта не обучена на данных, это вручную подобранные веса.
- Долговременного хранения данных нет, база данных не используется.

## Псевдокод пайплайна

```text
ввод: строка points_raw
points = разрезать по ';' → trim → убрать пустые
если points пустой → взять значения по умолчанию

coords = {}
для каждого города p в points:
    c = getCoords(p)
    если c не null:
        coords[p] = c
        добавить p в список валидных точек

distance = 0
для i от 0 до (n-2):
    distance += distanceKm(points[i], points[i+1], coords)

distance = round(distance)
count = количество точек
mode = predictTransportNN(distance, count)

сгенерировать googleUrl и yandexUrl
вывести всё в HTML
```
