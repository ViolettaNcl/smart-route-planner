# Логика «нейросети» для выбора транспорта

## Постановка задачи

Задача модели — по двум признакам маршрута выбрать удобный тип передвижения:

- суммарная дистанция маршрута в километрах;
- количество точек (городов) в маршруте.

Выходной класс:

- `пешком`;
- `авто`;
- `общественный транспорт`.

## Входные признаки и нормализация

Во входной функции `predictTransportNN($distance, $count)` используются два нормализованных признака:

- \( x_1 = distance / 1000 \) — расстояние в условных тысячах километров;
- \( x_2 = count / 10 \) — количество точек, приведённое к десяткам.

Это сглаживает масштаб значений и упрощает работу с весами.

## Весовые коэффициенты

Для каждого класса задаётся свой набор весов \( w_0, w_1, w_2 \):

```php
$W = [
    'walk' => [-3.0, -1.5, 2.0],
    'car'  => [ 1.0,  0.5, 0.5],
    'bus'  => [ 2.5,  1.2,-1.0],
];
```

Интерпретация:

- `walk` — штрафует большие расстояния и большое число точек, поощряет небольшие маршруты.
- `car` — нейтральнее к расстоянию и количеству точек, подходит для средних поездок.
- `bus` — предпочитает большие расстояния и умеренное число точек, имитируя междугородние поездки.

## Функция активации и выбор класса

Для каждого класса считается score по экспоненте линейной комбинации:

\[ score_k = e^{w_0 x_1 + w_1 x_2 + w_2} \] [1]

Реализация в коде:

```php
$scores = [];
foreach ($W as $k => $w) {
    $scores[$k] = exp($w*$x1 + $w*$x2 + $w);
}

$best = array_keys($scores, max($scores));
```

Мы не нормируем значения в вероятности (softmax), а просто берём класс с максимальным `score`. Затем класс переводится в человекочитаемое название транспорта:

```php
return match ($best) {
    'walk' => 'пешком',
    'car'  => 'авто',
    default => 'общественный транспорт',
};
```

## Примеры поведения

- Маленькое расстояние и мало точек → чаще `пешком`.
- Среднее расстояние (десятки–сотни км) → обычно `авто`.
- Большие расстояния (сотни–тысячи км) → `общественный транспорт`.

Пороговые значения задаются комбинацией весов, но интуиция понятна: модель имитирует простое человеческое решение.

## Ограничения модели

- Модель не обучена на реальных данных, это ручной классификатор.
- Не учитывается реальная дорожная сеть, пробки, скорости.
- Время в пути — это просто текущий timestamp, а не прогноз.

Тем не менее, схема демонстрирует идею мини‑«нейросети»: входные признаки, веса, нелинейность (exp) и выбор класса по максимальному отклику.
