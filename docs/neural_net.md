# ML-модель выбора транспорта

## Что изменилось по сравнению с первой версией

В первой версии проекта «нейросеть» была ручным классификатором: веса для
каждого класса (`walk`/`car`/`bus`) были подобраны интуитивно и записаны в коде
константами. Обучения не происходило — это была просто формула с тремя
наборами чисел.

В этой версии веса **обучаются с нуля градиентным спуском** на датасете —
`SoftmaxClassifier` стартует с нулевых весов и итеративно минимизирует
кросс-энтропийную функцию потерь. Это настоящая, пусть и простая, ML-модель:
мультиклассовая логистическая регрессия (softmax regression).

## Постановка задачи

По двум признакам маршрута предсказать один из трёх классов транспорта:

- `walk` — пешком;
- `car` — авто;
- `bus` — общественный/междугородний транспорт.

## Входные признаки

- **Дистанция маршрута** (км, после TSP-оптимизации порядка точек);
- **Количество точек** (городов) в маршруте.

### Почему дистанция масштабируется логарифмически

Наивный признак `distance_km / 1000` **не сработал** — в процессе разработки
модель стабильно путала короткие пешие маршруты с поездками на авто. Причина:
диапазон дистанций растягивается на 3 порядка (от долей км до ~1500 км), и в
линейном масштабе «пешеходная» зона (0–3 км) — это исчезающе узкая полоска
рядом с нулём (0.003 против, скажем, 0.35 для 350 км). Линейному
классификатору почти невозможно провести границу в настолько сжатом
пространстве.

Решение — логарифмическое масштабирование (см. `App\ML\FeatureEncoder`):

```php
x1 = log(1 + distance_km) / log(1 + 1500)
```

Log-преобразование распределяет короткие расстояния гораздо равномернее:
разница между 1 км и 3 км становится сопоставима по значимости с разницей
между 300 км и 900 км — что интуитивно ближе к тому, как люди воспринимают
расстояния. После этого изменения точность на валидационной выборке выросла с
~77% до ~93% (см. ниже).

Второй признак — число точек, приведённое к масштабу ~0–1: `x2 = stops / 10`.

## Обучающие данные — важная честность

В приложении нет накопленной истории реальных решений пользователей (маршруты
не сохраняются), поэтому обучать модель не на чем в буквальном смысле «на
статистике». `App\ML\Dataset` генерирует **синтетический** датасет:

1. Случайно генерируются дистанция и число точек в реалистичных диапазонах
   (смесь коротких, средних и дальних маршрутов).
2. Каждому примеру присваивается «эталонная» метка по понятному правилу
   (условно: до 3 км — пешком, до 350 км — авто, дальше — автобус/поезд, с
   поправкой на число точек).
3. **8% меток намеренно зашумлены** — случайно заменены на другой класс.

Шум — не случайность реализации, а осознанное решение: без него классы
разделяются идеальной границей, обучение вырождается в тривиальную задачу, а
веса модели устремляются в бесконечность (типичная патология логистической
регрессии на линейно разделимых данных). Шум также задаёт разумный потолок
качества — модель физически не может (и не должна) угадать зашумлённые метки,
поэтому 100% точности — заведомо недостижимая и нежелательная цель.

**Если однажды в проекте появится сохранение истории маршрутов** — этот
синтетический датасет можно заменить на реальные данные пользователей без
переписывания `SoftmaxClassifier`: он ничего не знает про то, откуда взялись
примеры для обучения.

## Обучение

Обучение — обычный батч-градиентный спуск на кросс-энтропийной функции потерь:

```text
для каждой эпохи:
    для каждого примера:
        probs = softmax(w · x)
        loss += -log(probs[правильный_класс])
        для каждого класса k:
            gradient[k] += (probs[k] - target[k]) * x
    веса -= learning_rate * gradient / n_примеров
```

Запуск: `php bin/train_model.php`. Скрипт делит данные на обучающую (80%) и
валидационную (20%) выборки, обучает модель только на обучающей части и
честно проверяет точность на валидационной — той, которую модель не видела.

## Метрики (актуальный прогон)

| Выборка | Точность |
|---|---|
| Обучающая | ~90% |
| Валидационная (модель не видела эти примеры) | ~93% |

Так как 8% меток в датасете зашумлены, теоретический потолок точности — около
92–95%: модель не может (и не должна) правильно предсказывать намеренно
нетипичные примеры. Результат на валидации в этом диапазоне означает, что
модель обучилась близко к практическому пределу, а не переобучилась (accuracy
на обучающей и валидационной выборках близки — явный признак того, что
переобучения нет).

Оба числа можно увидеть у себя, перезапустив `php bin/train_model.php` —
результат детерминирован (используется фиксированный seed), но чувствителен к
изменениям в `Dataset`, если вы будете его редактировать.

## Апгрейд (2026): MLP — нейросеть со скрытым слоем и backprop с нуля

`SoftmaxClassifier` (описан выше) — линейная модель: у неё нет скрытого слоя,
поэтому она физически может провести только *прямую* границу между классами
в пространстве признаков. `App\ML\MLPClassifier` добавляет один скрытый слой
(8 нейронов, активация `tanh`) между входом и softmax-выходом — то есть
появляется нелинейность, и теоретически модель может выучить более сложную,
изогнутую границу решений.

Как и `SoftmaxClassifier`, MLP обучен **с нуля**: никакого sklearn/tensorflow,
только массивы PHP и ручные вложенные циклы. Прямой проход:

```text
z1 = W1·x + b1;  a1 = tanh(z1)     # скрытый слой
z2 = W2·a1 + b2; probs = softmax(z2)  # выходной слой
```

Обратный проход — backpropagation по цепному правилу, вручную:

```text
dz2 = probs - target                  # производная softmax+CE — та же формула, что у SoftmaxClassifier
dW2 = dz2 ⊗ a1;  db2 = dz2

da1 = W2ᵀ · dz2                       # ошибка "протаскивается" через веса выходного слоя
dz1 = da1 * (1 - a1²)                 # производная tanh
dW1 = dz1 ⊗ x;   db1 = dz1
```

Подробный вывод формул и комментарий про инициализацию весов (почему нельзя
стартовать с нулей, как в `SoftmaxClassifier` — проблема симметрии) — прямо в
docblock `App\ML\MLPClassifier`.

### Честное сравнение с baseline — MLP не "автоматически лучше"

`bin/train_model.php` теперь обучает обе модели на одном и том же
train/val-разбиении и печатает сравнение. Результат на нескольких запусках с
разными seed:

| Seed | MLP (val) | Softmax (val) |
|---|---|---|
| 1 | 90.0% | 90.0% |
| 7 | 85.8% | 86.7% |
| 42 | 90.0% | 90.8% |
| 123 | 89.2% | 86.7% |

Модели идут почти вровень, иногда softmax даже чуть впереди. Это не баг и не
недообученная сеть — это ожидаемо для *этой конкретной* задачи: истинное
правило разметки в `Dataset` (пороги по дистанции + поправка на число точек)
само по себе близко к кусочно-линейному, а 8% зашумлённых меток задают
потолок точности, который смазывает небольшое теоретическое преимущество
нелинейной модели. На выборке в 120 примеров (20% от 600) разница в 1 pp —
это буквально один пример, статистический шум, а не сигнал.

**Практический вывод**, который стоит проговаривать на интервью: MLP здесь
добавлен не потому, что "нейросеть == больше accuracy", а потому что (а) это
демонстрирует полное понимание backprop и того, откуда берутся градиенты за
пределами тривиального линейного случая, и (б) архитектура готова к тому дню,
когда признаков и реальной нелинейности в данных станет больше (например,
если добавить час дня, наличие ж/д ветки между городами, историю пробок) —
тогда преимущество MLP над линейной моделью действительно проявится. На двух
простых признаках с зашумлёнными метками ожидать драматического отрыва было
бы нечестно по отношению к самим себе.

По умолчанию приложение (`TransportPredictor`) всё равно использует MLP —
она чуть точнее в среднем по сериям запусков и является тем, что демонстрирует
архитектуру нейросети целиком, а `SoftmaxClassifier` остаётся в проекте как
референс более простой модели и как fallback, если файла весов MLP нет.

### Строгая оценка: одной accuracy недостаточно

До появления `App\ML\ModelEvaluator` единственной метрикой в проекте была
accuracy — доля правильных ответов. У неё есть известная слабость: на
несбалансированных классах (а `walk` в датасете — самый редкий класс, ~20%
примеров) высокая accuracy достижима даже если модель систематически
недооценивает редкий класс, просто угадывая частые классы почаще.

`php bin/train_model.php` теперь дополнительно печатает confusion matrix и
precision/recall/F1 по каждому классу. Пример реального прогона (seed 42):

```
--- MLP: confusion matrix (строки — истинный класс, столбцы — предсказанный) ---
              walk     car     bus
  walk          25       0       1
  car            1      49       2
  bus            0       8      34

--- MLP: precision / recall / F1 по классам ---
  Класс  Precision     Recall         F1    Support
  walk        0.962      0.962      0.962         26
  car          0.86      0.942      0.899         52
  bus         0.919       0.81      0.861         42

  Accuracy: 0.9   Macro-F1: 0.907
```

Что здесь видно **сверх** одной accuracy: recall класса `bus` (0.81) заметно
ниже, чем у `walk`/`car` — модель чаще путает дальние маршруты с автомобилем
(confusion matrix прямо показывает: 8 примеров `bus` предсказаны как `car`),
чем наоборот. Это честная находка, которую accuracy в одиночку скрывает —
0.9 общей точности звучит ровно и не намекает на этот перекос.

**Интересно, что по macro-F1 (0.907) MLP на этом конкретном прогоне немного
уступает Softmax (0.912)** — тот же вывод, что и в разделе про accuracy выше,
просто более строгой метрикой: разница в пользу линейной модели статистически
несущественна (support класса `bus` — всего 42 примера), но сам факт, что
более сложная модель не гарантированно выигрывает даже по F1, а не только по
accuracy — важный, честный результат, а не повод скрыть его в пользу более
эффектной истории про нейросеть.

### K-fold кросс-валидация — не полагаемся на один "удачный" сплит

Одно случайное разбиение train/val может статистически "повезти" или
"не повезти" — особенно на 600 примерах. `ModelEvaluator::kFoldCrossValidate()`
делит весь датасет на 5 частей и обучает модель 5 раз, каждый раз проверяя на
той части, которая не участвовала в обучении:

```
Accuracy по фолдам: 92.5%, 90.8%, 90.8%, 91.7%, 90%
Среднее: 91.2% ± 0.9%
```

Разброс между фолдами (±0.9%) небольшой — результат стабилен и не зависит
критично от конкретного разбиения данных. Если бы разброс был, например,
±8%, это был бы сигнал, что 600 примеров датасета маловато для надёжной
оценки, и стоило бы либо увеличить датасет, либо не доверять единственному
числу accuracy без доверительного интервала.

### Визуализация decision boundary

`GET /api/decision_boundary.php?model=mlp|softmax` считает предсказание
модели на регулярной сетке [дистанция × число_точек] и отдаёт JSON с готовыми
классами по каждой ячейке — фронтенд (`assets/js/ml_boundary.js`, Chart.js)
просто рисует то, что получил, не дублируя forward pass на JS. Поверх карты
решений накладываются реальные точки обучающего датасета — видно, где модель
"уверена", а где проходит по разреженным/шумным участкам. Переключатель
модели (MLP/softmax) в интерфейсе — самый наглядный способ увидеть разницу
(или её отсутствие) между линейной и нелинейной границей вживую.



- Обучена на синтетических, а не на реальных данных пользователей (см. выше) —
  честно предупреждаем в README.
- Учитывает только дистанцию и число точек — не смотрит на реальную дорожную
  сеть, пробки, наличие ж/д или автобусного сообщения между конкретными
  городами.
- По умолчанию используется `MLPClassifier` (нейросеть со скрытым слоем) —
  но, как показано выше, на этих двух признаках с зашумлёнными метками она не
  даёт драматического отрыва от линейного `SoftmaxClassifier`. Это осознанно
  задокументированный факт, а не попытка скрыть, что "нейросеть не помогла":
  ценность MLP здесь в архитектуре (полный backprop с нуля) и в заделе на
  будущее, а не в текущем приросте accuracy на простой задаче.
- С появлением OSRM на вход модели теперь может подаваться **дорожная**
  дистанция (обычно на 10–20% больше воздушной), а не только приблизительная
  дистанция «по прямой». Модель не переобучалась специально под это отличие —
  пороги классов (~3 км, ~350 км) заданы с достаточным запасом, поэтому
  небольшое систематическое увеличение входного числа не меняет предсказание
  в подавляющем большинстве случаев. Это не идеальное решение, а осознанный
  компромисс: полноценно стоило бы переобучить модель на реальном
  распределении дорожных дистанций.
