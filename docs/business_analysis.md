# Бизнес-анализ и сценарии использования

## Цель приложения

Сервис помогает пользователю быстро спланировать поездку между несколькими
городами: не просто оценить расстояние, а получить **готовый эффективный
порядок объезда** точек, честную оценку дистанции, времени и стоимости,
подсказку по подходящему транспорту, погоду и точки интереса по маршруту,
план по дням для дальних поездок и человеческий AI-совет — с наглядной
интерактивной картой.

Полезно при:

- планировании поездки по нескольким городам, когда порядок объезда не
  очевиден заранее;
- решении, есть ли смысл ехать на машине или лучше выбрать общественный
  транспорт;
- прикидке бюджета поездки (топливо/билеты) и её экологического следа (CO2);
- планировании дальней поездки на несколько дней вождения — где разумно
  остановиться на ночь;
- быстрой проверке погоды и наличия заправок/кафе/отелей по пути, не открывая
  для этого отдельные сервисы;
- быстрой визуальной оценке маршрута на карте перед тем, как открывать
  Google Maps или Яндекс.Карты для навигации.

## Основные роли

- **Пользователь** — человек, который планирует поездку, вводит список
  городов и (опционально) настраивает параметры расчёта стоимости.

## Ключевые бизнес-процессы

### 1. Ввод маршрута

1. Пользователь вводит список городов одной строкой, разделяя их `;` —
   с автоподсказками при вводе (`api/suggest.php`, живой поиск через
   Nominatim, навигация клавиатурой).
2. Система удаляет лишние пробелы и пустые элементы.

### 2. Геокодирование городов

1. Для каждого города отправляется запрос к Nominatim (с кэшированием —
   повторный запрос того же города не идёт в сеть повторно).
2. Если координаты найдены, точка участвует в маршруте.
3. Если город не распознан, он явно попадает в список «пропущенных» и
   показывается пользователю предупреждением — не теряется молча.
4. Если валидных точек меньше двух — пользователь получает понятную ошибку
   вместо пустого/некорректного результата.

### 3. Оптимизация порядка объезда

1. Система строит начальный маршрут эвристикой «ближайший сосед».
2. Локальный поиск (2-opt) убирает пересечения и дополнительно сокращает путь.
3. Первая введённая точка остаётся стартом — маршрут не переставляет точку
   отправления пользователя.

### 4. Расчёт дистанции и построение маршрута по дорогам

1. Система пытается построить реальный маршрут по дорогам через OSRM —
   получает точную дистанцию, время в пути (для авто) и геометрию трассы для
   отображения на карте.
2. Если сервис маршрутизации недоступен, система прозрачно откатывается на
   расчёт «по воздуху» (формула гаверсинусов) и прямые линии между точками —
   пользователь видит явную пометку, какой источник данных использовался.

### 5. Подбор транспорта, времени, стоимости и выбросов CO2

1. На вход обученной модели передаётся суммарная дистанция (дорожная, если
   доступна, иначе «по воздуху») и количество точек; модель выбирает тип
   транспорта и показывает «уверенность» предсказания.
2. Каждому визиту случайно (50/50) назначается одна из двух моделей —
   MLP или Softmax — для непрерывного A/B-тестирования качества
   предсказаний в проде (см. п. 9).
3. Время в пути: точное — от OSRM, если предсказан автомобиль; для пешей и
   общественной поездки — приблизительная оценка по средней скорости, что
   явно помечено в интерфейсе знаком «≈».
4. Стоимость поездки оценивается по предсказанному транспорту (топливо ×
   расход × цена литра для авто, либо цена билета за км для общественного
   транспорта) — параметры расчёта можно поменять прямо в интерфейсе.
5. Выбросы CO2 оцениваются по усреднённым коэффициентам на пассажиро-километр
   для предсказанного вида транспорта — наглядное сравнение, не бухгалтерски
   точный отчёт.

### 6. Визуализация маршрута

1. Точки и путь между ними отображаются на интерактивной карте (Leaflet) —
   линия маршрута повторяет реальные дороги, если доступна геометрия от OSRM.
2. Дополнительно формируются ссылки на Google Maps и Яндекс.Карты для
   пошаговой навигации.

### 7. Шеринг маршрута

1. Пользователь может скопировать ссылку, в которой закодирован весь список
   городов (без сервера и без базы данных).
2. Получатель ссылки открывает её и сразу видит рассчитанный маршрут — расчёт
   происходит автоматически при загрузке страницы.

### 8. Погода и точки интереса по маршруту

1. По кнопке пользователь может подтянуть погоду по каждой точке маршрута
   (Open-Meteo) — с предупреждением о сильном дожде, жаре, морозе или грозе.
2. По отдельной кнопке — точки интереса рядом с маршрутом (АЗС, кафе,
   рестораны, отели) через Overpass API — "умные остановки" на длинных
   маршрутах.
3. Обе фичи — необязательные, отдельные вызовы уже после основного расчёта:
   не расходуют лимиты бесплатных API и не блокируют и не ломают основной
   сценарий, если сервис недоступен.

### 9. AI-планировщик по дням и AI-совет по поездке

1. Если маршрут длинный, K-Means (unsupervised, без разметки) делит его на
   сбалансированные по километражу дни вождения, не нарушая порядок городов
   — подсказка, где разумно закончить день, а не бронирование отеля.
2. Отдельно, LLM (Anthropic/OpenAI, если задан ключ API) генерирует
   человеческий комментарий к поездке: где сделать привал, нужна ли ночёвка
   на длинном перегоне, стоит ли обратить внимание на погоду. Без ключа API
   работает офлайн rule-based fallback — интерфейс честно помечает, какой
   вариант сработал.

### 10. A/B-тест и живое дообучение модели

1. Каждому визиту случайно назначается модель (MLP или Softmax) на весь
   визит; после расчёта маршрута пользователь может отметить 👍/👎, угадала
   ли она — статистика по обеим моделям копится и видна прямо в интерфейсе
   (карта решений модели → A/B-тест).
2. Пользователь может поправить предсказание модели ("на самом деле это
   автобус, а не машина") — сервер делает один шаг дообучения (только для
   MLP) и сохраняет обновлённые веса; отдельная кнопка сбрасывает модель к
   изначально обученному состоянию. Демо-механика: веса общие для всех
   посетителей сайта, не изолированы по пользователю.

### 11. Локализация и установка как приложение

1. Весь интерфейс переключается между 🇷🇺 русским и 🇬🇧 английским одной
   кнопкой без перезагрузки страницы; выбор сохраняется между визитами.
2. Сайт можно установить на телефон как PWA-приложение (манифест + service
   worker с офлайн-кэшем оболочки интерфейса).

## Нефункциональные требования

- **Простота развёртывания**: не требует базы данных; Composer нужен только
  опционально (для генерации автозагрузчика), встроенный автозагрузчик
  работает без него.
- **Отказоустойчивость**: нераспознанные города, недоступность OSRM,
  Overpass, Open-Meteo или LLM не ломают основной сценарий — каждая фича
  деградирует независимо и честно помечает это в интерфейсе.
- **Отзывчивость интерфейса**: расчёт и все дополнительные фичи работают
  через fetch без перезагрузки страницы.
- **Защита от перегрузки**: свой rate limiter (token bucket) ограничивает
  частоту обращений к бесплатным внешним API и демо-эндпоинтам живого
  обучения, не давая одному клиенту исчерпать общий лимит для всех.

## Технические ограничения

- Приложение работает без базы данных: единственное постоянное состояние —
  файловый кэш геокодирования, состояние rate limiter'а, статистика A/B-теста
  и веса модели после живого дообучения.
- История маршрутов не сохраняется — обновление страницы сбрасывает состояние
  формы (но не общие для сайта файлы на диске выше).
- Погода, точки интереса и AI-совет зависят от доступности сторонних
  бесплатных сервисов без SLA — при их недоступности приложение просто не
  показывает соответствующий блок, не ломая расчёт основного маршрута.
