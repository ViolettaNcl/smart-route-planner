# Бизнес‑анализ и сценарии использования

## Цель приложения

Сервис помогает пользователю быстро прикинуть маршрут между несколькими городами, оценить примерную длину поездки и выбрать подходящий способ перемещения.

Полезно при:

- предварительном планировании поездок по России;
- решении, есть ли смысл ехать на машине или лучше выбрать общественный транспорт;
- быстрых оценках: насколько «растянут» маршрут.

## Основные роли

- **Пользователь** — человек, который планирует поездку и вводит список городов.

## Ключевые бизнес‑процессы

### 1. Ввод и валидация маршрута

1. Пользователь вводит список городов одной строкой, разделяя их `;`.
2. Система удаляет лишние пробелы и пустые элементы.
3. Если ни одна точка не введена, используются значения по умолчанию (например, Волгоград–Ростов-на-Дону).

### 2. Геокодирование городов

1. Для каждого города отправляется запрос к Nominatim.
2. Если координаты найдены, точка добавляется в маршрут.
3. Если координаты не найдены, точка пропускается без ошибки для пользователя.
4. Между запросами есть небольшая задержка для бережного использования API.

### 3. Расчёт дистанции

1. Система проходит по маршруту в указанном порядке.
2. Для каждой пары соседних точек рассчитывается расстояние по формуле гаверсинусов.
3. Все отрезки суммируются и результат округляется до целых километров.

### 4. Подбор транспорта

1. На вход модели передаётся суммарная дистанция и количество точек.
2. Модель выбирает один из трёх типов транспорта.
3. Выбранный тип показывается пользователю в карточке результата.

### 5. Построение маршрута в картах

1. По списку точек формируются URL для Google Maps и Яндекс.Карт.
2. Пользователь может одним кликом открыть маршрут в выбранном картографическом сервисе.

## Нефункциональные требования

- Простота: интерфейс состоит из одной страницы и одной формы.
- Отказоустойчивость: некорректные или нераспознанные города не ломают сценарий.
- Лёгкость развёртывания: достаточно скопировать три файла на PHP‑сервер.

## Возможные улучшения

- Добавить оценку времени в пути с учётом типа транспорта.
- Поддержать оптимизацию порядка точек (поиск кратчайшего маршрута).
- Сохранять историю маршрутов пользователя.
- Перевести «нейросеть» на настоящую обученную модель (например, отдельный Python‑сервис).

## Технические ограничения

- Приложение работает без базы данных, все данные обрабатываются в рамках одного запроса.
- История маршрутов не сохраняется, при обновлении страницы расчёт выполняется заново.
